## Problem Description

The Data Deduplicator tool produces **non-deterministic output** where identical input data generates different results across different runs and Python processes. The same deduplication operation produces:
- **Run 1:** `"Unique IDs: 1, 2, 3"`
- **Run 2:** `"Unique IDs: 2, 3, 1"`
- **Run 3:** `"Unique IDs: 3, 1, 2"`

### Root Cause
The `deduplicate_records()` function returns Python **set objects** (`seen_ids`). Python sets have **undefined iteration order** (affected by PYTHONHASHSEED), causing:
1. Non-deterministic iteration order across runs
2. Non-deterministic summary string generation
3. Non-deterministic report ID generation (based on hash of summary)
4. Flaky tests that randomly fail

### Problem Impact
- Same input produces different outputs on each run
- Report IDs are non-deterministic
- Tests randomly fail depending on process execution order
- System behavior is unpredictable

def deduplicate_records(records):
    seen_ids = set()

**Fixed:**
```python
def deduplicate_records(records):
    seen_ids = set()
    unique_records = []
    
    for record in records:
        if record['id'] not in seen_ids:
            seen_ids.add(record['id'])
            unique_records.append(record)
    
    return unique_records, sorted(seen_ids)  # ✅ Returns sorted list (deterministic)
```

# Critical Implementation Notes

## The Core Fix

**Problem:** Set iteration order is undefined → non-deterministic output

**Solution:** Convert set to sorted list before returning

```python
# ❌ BUGGY (non-deterministic)
return unique_records, seen_ids  # Returns set

# ✅ FIXED (deterministic)
return unique_records, sorted(seen_ids)  # Returns sorted list
```

This single change fixes all non-determinism:
- Output order becomes deterministic (alphabetical sort)
- Summary strings become consistent
- Report IDs become deterministic
- Tests pass reliably

## Why This Works

1. **Internal set** = efficient duplicate detection (O(1) lookup)
2. **Final sort** = deterministic order (same every time)
3. **Result:** Combines best of both - efficient + deterministic

## Common Pitfalls to Avoid

1. **Don't just use lists everywhere** - Sets are more efficient for duplicate detection
2. **Don't forget to sort** - Just converting set to list doesn't fix non-determinism
3. **Don't change function signatures** - Keep them accepting the same data types
4. **Don't skip testing** - Need extensive validation to prove determinism
5. **Don't forget edge cases** - Test numeric strings, mixed case, special chars
